# Frozen Core Iteration

Identify the authoritative input version and the layer that is meant to change. Separate simulation/data, player operations, information disclosure, visible feedback, and fiction. Preserve formulas, operation order, rounding, RNG and save semantics unless the task actually authorizes changing them.

For first-run game work, disclose a system after an event gives it meaning. Do not automatically turn the game into a dashboard of future systems. Check representative states in the actual camera/layout; a model viewer is not game-context proof.

Validate the protected contract and inspect the changed experience. A preserved engine or passing tests does not establish fun. If a requested experience truly requires a core change, explain that conflict with a concrete example rather than silently changing the boundary.
