# Long Running System Audit

Start from fresh primary state and the current unfinished checks. Reuse completed evidence only while the input and scope still match. Keep formal data separate from fixtures and experiments.

Follow the real time sequence. Later corrections must not be overwritten by older asynchronous results. Distinguish draft, queued, channel-delivered, acknowledged and human-observed states. For devices, distinguish built package, installed app, cold start, permissions, local network, cross-network and restart behavior.

For memory/context systems, distinguish source read, formal fact, context inclusion, model receipt and observable recall. A database field does not prove the experience. Isolated passes do not establish production cutover or long-running reliability; retain concrete FAIL/NO_GO results and stop only the affected branch.
